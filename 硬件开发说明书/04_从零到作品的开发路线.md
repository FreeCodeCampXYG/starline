# 从零到作品的开发路线

## 阶段 0：认板，不先接线

拍摄主板正反面、记录丝印、PCB 版本、音频板版本、连接器 pin-1 方向和供电标记。当前资料里 `XJWB03`/`LJWB76`、`LJX40-Audio-KIT`/`LJX40-Audio-Core` 关系未确认；在映射确认前，不把一张 GPIO 表套给另一块板。

## 阶段 1：建立“电源—信号—资源”账本

为每个模块记录：模块完整型号、供电范围、正常/启动/堵转电流、逻辑高低门限、接口类型、引脚方向、有效电平、板载电阻/稳压/驱动器、与主板 GPIO 的对应关系、证据来源和验证状态。

遇到 GPIO 表时，分别标成 `芯片支持`、`当前固件选择`、`板上已核对连线` 三列。只有第三列能由当前板原理图或实测确认的资源，才可直接用作物理接线合同。

## 阶段 2：先做电源检查

1. 断电检查 VCC-GND 是否短路、连接器是否反插。
2. 使用限流电源或受控 USB 供电，先确认空载输入电流。
3. 测量各稳压轨，记录纹波和启动压降；示波器测量时使用短地弹簧。
4. 先接一个模块，观察启动和动作瞬间的电压，不同时接多个大电流负载。
5. 若加入舵机/马达后 ESP32 重启，先查电源跌落、回流路径和共地，再查业务代码。

## 阶段 3：单模块最小验证

- I2C 传感器：确认供电和上拉电平，扫描 7-bit 地址，读取 WHO_AM_I，再读原始传感器寄存器。保留原始日志，不跳过身份检查。
- 舵机：先只输出安全中位附近的脉冲，限制脉宽范围，外部供电并共地，确认不碰止挡后再校准角度。
- 振动模块：先测 VCC/IN/GND 标签和输入极性；用 GPIO 控制逻辑输入，不将裸马达挂在 GPIO。
- WS2812：先单颗低亮度测试，再增加到整圈；确认 VDD、GND、数据电平、GRB 顺序、复位低电平时间。
- 摄像头：先确认 FPC 正反方向、2.8 V 轨、24 MHz 时钟源和 1-bit SPI 引脚映射，再启用相机宏；同时释放 GPIO4/GPIO8 冲突。

## 阶段 4：软件集成与构建验证

1. 记录基线提交和当前 `qm_config.h`、`sdkconfig`、`partitions.csv`。
2. 一次只改一个外设或一个宏；先运行对应 BSP 的单项验证。
3. 合并功能后检查 GPIO 冲突、总电流、任务栈/内存和分区容量。
4. 现场构建准备见 [07_现场离线编译准备](07_现场离线编译准备.md)。当前已验证 PowerShell export + `idf.py build`；仓库 `dev.bat` 写死 Python 3.14 环境名，与本机准备的 Python 3.12 环境不一致，不能直接照搬。
5. 构建成功只证明软件构建完成，不等于实际电压、电流、温升和通信时序已通过。

## 阶段 5：形成可复现记录

每个作品至少保留：板卡与模块身份照片、原理图版本、接线图、供电树、GPIO 表、固件提交、编译配置、仪器和测量点、测试条件、结果、未解决风险。

## 一个推荐的学习项目序列

1. 只读 GPIO 输入/输出：先用 LED 或限流逻辑输入理解高低电平。
2. MPU6050：验证 I2C 地址与原始加速度/角速度，再加入坐标轴和静止偏置。
3. WS2812：验证一颗灯、GRB 顺序和逻辑电平，再驱动整圈。
4. 振动模块：验证数字输入/输出控制，再测启动时电源压降。
5. 舵机：用外部电源和限幅脉宽做位置标定，记录止挡和峰值电流。
6. 摄像头：先跑 1-bit SPI 最小取流，再加入图像处理；确认 GPIO4/GPIO8 冲突和相机时钟。
7. 最后组合成作品：先设计电源与接口，再加入 UI/联网/业务逻辑。
