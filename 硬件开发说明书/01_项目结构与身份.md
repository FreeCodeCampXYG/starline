# 项目结构与板卡身份

## 仓库是什么

该仓库是 ESP32-S3 组合开发板的固件 SDK 与示例应用，不是完整的主板 PCB 设计仓库。当前检出提交为 `89020f5e04bf777ae1672b8f3d320bc6e0ef3e0c`，时间 `2026-10-23`。

```text
仓库根目录
├── apps/                 ESP-IDF 应用工程、分区表、sdkconfig
│   └── main/
│       ├── main.c         启动编排与插件初始化
│       ├── qm_config/    产品和功能宏
│       ├── peripheral/   GPIO、传感器、相机、舵机、马达、灯带 BSP
│       ├── voice/        音频创建和开机音效
│       ├── cloud/        配网、联网和云端方法分发
│       ├── agent/        语音会话封装
│       ├── lj_components/业务插件
│       └── pose/         姿态识别示例
├── components/           外部组件与托管组件
├── qumios-dev/           QUMIOS 平台组件源码
├── esp-idf/              ESP-IDF 源码
├── doc/                  外设规格书、模块原理图和转接板资料
└── tools/                安装、构建和 CI 辅助工具
```

`apps/main/CMakeLists.txt` 从 `qm_config/qm_config.h` 读取宏并决定是否把插件源文件加入组件；`main.c` 负责应用初始化。`bsp_*.c/.h` 描述当前固件如何驱动外设，不等同于 PCB 的真实电气连接证明。

`esp-idf/` 和 `qumios-dev/` 在当前 Git 树中是普通目录树；仓库没有 `.gitmodules`。手册中“子模块未拉全时执行 submodule update”的描述与当前仓库结构不一致。当前分析克隆是 `blob:none` 的稀疏工作树，不能直接用于完整编译。

## 当前固件功能状态

提交中的 `apps/main/qm_config/qm_config.h` 与仓库 README/手册有配置漂移。以当前构建输入为准：

| 项目 | 当前宏/代码 | 当前分析结论 |
| --- | --- | --- |
| 闹钟 | `CONFIG_QM_ALARM_SUPPORT=1` | 该提交编入闹钟代码 |
| 资源播放 | `CONFIG_LJYD_PLAYBACK_SUPPORT=1` | README 写默认关闭，当前宏为开启 |
| 姿态识别 | `CONFIG_QM_POSE_SUPPORT=1` | README/手册写默认关闭，当前宏为开启 |
| 摄像头取流 | `CONFIG_APP_CAMERA_TEST=0` | BSP 不作为当前默认功能启动 |
| 番茄钟 | `CONFIG_QM_POMODORO_SUPPORT=0` | 当前宏为关闭 |
| MPU6050 | `main.c` 中初始化被注释 | BSP 存在，不代表默认运行 |
| 舵机、震动、WS2812 | `main.c` 中示例初始化被注释 | 示例驱动存在，不代表默认运行 |

## 配置与文档冲突

- 当前 `apps/partitions.csv` 把 NVS 固定在 `0x11000`；使用说明 PDF 写成 `0x9000`。构建时以实际分区 CSV 为准，重新生成烧录参数前再次核对偏移和镜像。
- `README.md`、上手手册与当前宏值有多处功能默认状态差异；任何功能是否启用，都从本次构建使用的 `qm_config.h` 和构建结果核对。
- 仓库 README 的产品配置示例含有明文云端密钥风险。本文不复述值，也不把它作为硬件信息；应由仓库维护者核验、轮换并检查历史版本。

## 分层理解固件

```text
产品应用与插件  apps/main/main.c、cloud/、agent/、lj_components/
板级抽象       apps/main/peripheral/bsp_*.c/.h
平台组件       qumios-dev/ 与 components/
芯片 SDK       esp-idf/，当前应用 sdkconfig 目标为 ESP32-S3
物理电路       主板完整原理图/BOM 未提供；不能由 BSP 单独还原
```
